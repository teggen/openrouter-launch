# Project Review — openrouter-launch

**Date:** 2026-08-16
**Reviewer:** GLM-5.3 (independent code review)
**Scope:** full tree — `main.go`, `internal/{agent,cli,config,launch,openrouter,tui,ui,version}`, CI workflows, Makefile, README/CLAUDE docs. Prior review documents were deliberately not read, per instruction.

**Verification performed during this review:**

- `go build ./...` — clean
- `go vet ./...` — clean
- `go test ./... -count=1` — all 10 packages pass

---

## 1. Executive summary

This is an unusually well-engineered small Go CLI. The architecture is a strict
one-directional pipeline (`cli → launch → agent`, with `tui` and `openrouter` as
side inputs), purity is enforced where it matters (every `Launcher.Command` is a
pure function testable by struct comparison), all user-visible conditions are
returned as *data* (typed errors + `Warning` values) rather than printed, and
every persistent write is atomic (temp-file + rename) with mode preservation.
The "zero-touch" principle — never write an agent's own config except through
the capability-gated, restoring `ConfigWriter` — is not just documented but
**machine-checked** by `TestWriteSitesAreExhaustivelyEnumerated`
(`writesites_test.go`), which greps the whole tree for write primitives and pins
them to a five-file allowlist.

The comment discipline is exceptional: load-bearing invariants ("Landmine N")
are explained in place, with the reasoning attached rather than delegated to a
lost lookup table. Tests are extensive and the project's own stated convention
(mutation-check every new test) is the right one.

I found **no Critical or High defects**. Findings below are Medium and lower:
one real robustness gap in price parsing (negative sentinel values), a few
low-severity behavioral edges, and informational notes. None of them undermine
the tool's central claims.

## 2. Strengths

1. **Architecture.** Clean layering with no cycles (test-enforced:
   `TestTUIDependsOnNeitherCLINorCobra`). `internal/launch` never touches the
   terminal; `internal/cli` and `internal/tui` are two renderers of the same
   planner. Dependency injection is via struct fields (`Service.Catalog`,
   `Service.Run`, `tuiFunc`), not process-global mutation — testable by
   construction.

2. **The purity contract.** `Launcher.Command` is pure for every agent, which
   makes all eleven launchers testable by comparing a `Command` struct. The
   write/io side effects are segregated into capability interfaces
   (`ConfigWriter`, `Staged`, `CredentialShadowCheck`) detected by type
   assertion — an agent that cannot be driven by env/argv simply does not
   implement them.

3. **Warnings as data.** `Plan` returns warnings accumulated *before* a fatal
   guard alongside the error, and both the CLI and TUI render them before
   inspecting the error. This fixes the classic "the stale cache explains the
   unknown-model failure but the error path dropped it" bug class.

4. **Honest pricing semantics.** "Unknown pricing is never free" is enforced
   consistently in three places: `Model.IsFree()`, the `--max-price` filter
   (unknown excluded), and `unknownLast` in sorting (decided *before* the Desc
   swap so unknown stays at the bottom either direction). `FormatPrice` renders
   `?` / `<$0.01` rather than lying with `$0.00`.

5. **Env handling.** `ExecArgs` deduplicates inherited env entries whose keys the
   command overrides — correct for `execve(2)` semantics where POSIX `getenv`
   returns the *first* match and naive appending would let a stale user export
   win. This is exactly the kind of bug most launchers ship with.

6. **Atomic, mode-preserving writes.** `config.Save` (explicit 0600 chmod on the
   temp file), `writeDroidSettingsFile` and `writeClineProvidersFile` (preserve
   the prior file's mode — droid's file can hold *real* API keys in foreign
   entries, so never broadening 0600→0644 is load-bearing), temp file in the
   target directory then `os.Rename`.

7. **Exit-code propagation.** `main.exitCode` matches structurally on
   `ExitCode() int`, which is what lets the Windows wait-path and the Unix
   `RunWait` (ConfigWriter) path propagate the agent's own exit status while
   remaining unit-testable. Cobra's redundant error line is silenced only for
   that case (`isAgentExitError`).

8. **TUI teardown discipline.** One bubbletea program per screen, `Run` never
   launches — the caller runs `Service.Launch` only after every program has
   returned, so the agent never inherits a raw-mode terminal. The `escLatch`
   (split alt-chord vs. bare ESC) is a genuinely subtle terminal problem solved
   correctly with reasoning documented inline.

9. **Security posture.** API key is read from env or a 0600 config file and
   never written anywhere else; the one argv exposure (cline `-k`) is a
   documented, measured, owner-accepted decision with the `/proc/<pid>/cmdline`
   caveat printed in the README. Config dir 0700 with a correct macOS `staff`
   rationale. No network call in the launcher path beyond the public catalog
   endpoint.

10. **Test quality culture.** Adversarial fixtures (200-char descriptions to
    exercise the width cap), injection seams so tests never consult `PATH` or
    `$HOME` (Landmine 8), machine-checked invariants (write sites, goreleaser
    ldflags ↔ version symbols, sort-label ↔ table-header alignment), CI legs on
    all three OSes with a dedicated machine-independence job, coverage floor.

## 3. Findings

### Medium

#### M1. Negative price sentinels parse as valid (near-free) prices
**File:** `internal/openrouter/model.go`, `perMillion` (~line 92)

OpenRouter's API has historically used negative values (notably `"-1"`) in
`pricing.prompt` / `pricing.completion` to signal *unknown / not applicable*
pricing for some entries. `strconv.ParseFloat("-1", 64)` succeeds, so the model
is recorded with `PromptPricePerM = -1_000_000` and — critically —
`PricingUnknown = false`. Consequences:

- `FormatPrice` renders `"<$0.01"` (the negative fails the `usdPerM == 0` check
  and passes the `usdPerM < 0.005` check) — the model looks nearly free, which
  is precisely the false claim Landmine 4 exists to prevent.
- `--max-price` admits it (`-1e6 > ceiling` is false, `PricingUnknown` is
  false), so a cheapest-first filtered list can be headed by a model whose price
  is simply unknown.
- Ascending `--sort input/output` puts it at the very top; `unknownLast` never
  fires because the unknown flag is not set.

The test fixture (`testdata/models.json`) contains only `"0"`, `"0.0000011"`,
and `"0.000015"`, so this path is untested. **Fix:** in `perMillion`, treat
`v < 0` as `ok = false` (or clamp and mark unknown). One line plus a fixture
entry pinning `"-1"`.

*Caveat:* this is Medium confidence on API behavior — if the current
`/models` endpoint never emits negative strings, the code is correct as
written; the fixture should still pin the case defensively, since the failure
mode is silent.

### Low

#### L1. `rejectModelFlag` / `rejectFlags` false positives on short-flag prefixes
**File:** `internal/agent/args.go`

`strings.HasPrefix(arg, "-m") && len(arg) > 2` rejects *any* argument beginning
`-m…` — a legitimate passthrough like `-mode`, `-max-tokens`, or `-memory`
hypothetically supported by an agent would be refused with the misleading
message "conflicting argument … openrouter-launch manages the model". Same
shape for `-P…` / `-k…` in `rejectFlags`. The conservatism is defensible (a
false negative silently launches the wrong model; a false positive costs a
renamed flag), but the error text asserts an intent the user may not have had.
Consider: restrict the attached form to `-m<slug-like>` heuristics, or at least
word the message as "looks like a model flag" for prefix matches.

#### L2. `stageFiles` writes non-atomically
**File:** `internal/launch/handoff.go` (~line 80)

The staged-file materializer uses plain `os.WriteFile`, while every other
persistent write in the tree follows the temp+rename "Landmine 9 shape". A crash
mid-write leaves a truncated `openclaw.json`. Impact is low (the file is
launcher-owned, contains no secret, and is rewritten on every launch), but it is
an inconsistency with the project's own stated invariant, and the fix is the
same three-line pattern used in `config.Save`.

#### L3. `RunWait` can double-deliver SIGINT
**File:** `internal/agent/exec_wait.go`

The parent stays in the terminal's foreground process group with the child, so
Ctrl+C delivers SIGINT to **both**; the parent's handler then forwards a second
one. Harmless for agents that treat interrupt idempotently, but an agent that
counts interrupts (one press cancels the current operation, two exits) would see
one keypress as two. At minimum, document the duplication next to the forward;
the full fix (child in its own process group, exclusive forwarding) changes
terminal-signal semantics and needs care.

#### L4. Unbounded `io.ReadAll` on the catalog response
**File:** `internal/openrouter/client.go`

A misbehaving or MITM'd endpoint could stream an arbitrarily large body. Wrap in
`io.LimitReader` (the real catalog is a few MB; 32–64 MiB is a generous cap)
and return a clear error past it. Low likelihood, cheap fix, and it is the only
network read in the binary.

#### L5. Concurrent launcher sessions race on ConfigWriter files
**Files:** `internal/agent/droid.go`, `internal/agent/cline.go`

No locking guards `~/.factory/settings.local.json` or cline's
`providers.json`. Two overlapping cline launches can interleave snapshot /
cline-persist / restore so that the second snapshot captures the *launcher's*
key and restores it as if it were the user's — the exact leak `Apply` exists to
prevent, reachable only through concurrent sessions of the same agent. An
advisory note in the README ("don't run two cline/droid sessions through the
launcher at once") or a lockfile under our config dir would close it. Edge
case; not a defect in the single-session model the tool assumes.

### Informational

- **I1. Write-site tripwire coverage.** `writeSitePattern` greps six primitives
  (`os.WriteFile`, `os.Create(`, `os.OpenFile`, `os.MkdirAll`, `os.Rename`,
  `os.CreateTemp`). A write via an `*os.File` handle obtained otherwise (e.g.
  `os.Open` + `f.Write`, or shelling out) would bypass it. The allowlist
  discipline is still valuable; just be aware it pins the *idioms this codebase
  uses*, not the Go standard library's full write surface.
- **I2. `confirm` blocks on stdin.** `cli/launch.go`'s prompt reads until
  newline/EOF with no TTY check; a script holding stdin open would hang at the
  prompt. Consistent with interactive-tool conventions; a TTY check with an
  auto-decline (or an error telling the user to pass `--yes`) would be friendlier.
- **I3. Empty catalog forces refetch.** `Cache.read` treats `len(models) == 0`
  as a miss (guarding truncated writes). If the API ever legitimately returns
  zero models, every run refetches. Harmless as designed.
- **I4. `Suggest` quality.** A short unknown slug (e.g. `gpt`) yields five
  loosely-matching suggestions in catalog order rather than the five *closest*;
  the ranking logic exists in `internal/tui/match.go` but is not reused here.
  Cosmetic.
- **I5. Landmine numbering.** Numbers up to 38 are cited with no lookup table
  in-tree (authors acknowledge this in CLAUDE.md, pointing at
  `git show 582c6a9:HANDOFF.md`). Every citation does carry its reasoning
  inline, so this is fine — but new citations should keep doing so, or the
  numbers will rot faster than the prose.
- **I6. Fixed table width.** `ui.MaxTableWidth = 100` ignores the actual
  terminal width by deliberate, documented decision (avoiding an
  `x/term` dependency). Accepted trade-off; noting for completeness.
- **I7. `go.mod`** declares `golang.org/x/sys` as indirect at v0.36.0; the
  README records a parked bump. Nothing actionable from static review.

## 4. Verification notes

- The five-write-site enumeration was cross-checked against the code: sites 1–5
  (`cache.go`, `config.go`, `handoff.go`, `droid.go`, `cline.go`) each contain
  write primitives, and no other non-test file matched the primitive set —
  consistent with `writeSiteAllowlist`.
- `droid.Apply`'s restore path was traced: marker-owned entries only,
  `customModels` shape-refusal, JSON-null exemption, mid-session user edits
  preserved, file removal when it created the file and nothing else remains —
  all correct.
- `cline.Apply`'s snapshot/restore (including the refusal-to-launch when the
  file is unreadable-but-present, the no-file restore that removes the persisted
  key, and mode reproduction from the file actually read) was traced and is
  correct.
- The `--desc`-without-a-sort-column guard in `models.go` handles the explicit
  `--desc=false` form correctly (only a merged `Desc == true` is rejected).
- The TUI driver's error taxonomy (`noticeThen` vs `noticeThenFatal` vs
  `noticeThenDone`, `retreat`, `rootOrDone`) was traced; the documented
  exit-0-vs-exit-1 fix lives in `noticeThenFatal` as described.

## 5. Recommended priorities

1. **M1** — one-line negative-price guard in `perMillion` + fixture entry
   pinning `"-1"`. Highest value-per-line in this list.
2. **L4** — `io.LimitReader` on the catalog response.
3. **L2** — make `stageFiles` atomic (reuse the temp+rename shape).
4. **L3 / L5** — document (or lock) the concurrency and signal-duplication
   edges.
5. **L1** — message wording for prefix-match rejections.

Everything else is optional polish on an already disciplined codebase.
